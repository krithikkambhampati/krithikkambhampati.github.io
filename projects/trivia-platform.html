Overview

Every room runs as a synchronized game loop on the server — clients never decide correctness or timing themselves, they just render whatever state the server broadcasts. That server-authoritative design is what keeps 15+ players in a room seeing the same question, the same clock, and the same leaderboard at once.

Scoring under contention

  • Server-authoritative timers mean the clock a player sees is advisory — the server's clock is what actually decides if an answer counted.
  • Speed-weighted scoring rewards faster correct answers, computed only after the server closes the answer window.
  • Redis optimistic locking keeps score updates race-condition-safe when many players answer within milliseconds of each other.

Scaling out

State updates fan out to all clients in a room via WebSocket broadcasts routed through Redis pub/sub, which decouples the game-loop process from the connection layer — new server instances can pick up rooms and broadcasts without every player needing to reconnect to the same process.
