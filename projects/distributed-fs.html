Distributed Network File System

A distributed file system built from scratch in C, with a centralized Name Server coordinating multiple Storage Server nodes over a custom binary protocol.

Overview

The system separates naming from storage: a single Name Server tracks where every file lives and routes client requests, while multiple Storage Server nodes hold and serve the actual data. Clients never talk to storage nodes directly for metadata — every operation is authorized and located through the name server first, which keeps the namespace consistent even as storage nodes join, leave, or fail.

Concurrency & correctness

  • Sentence-level locking for concurrent writes — multiple clients can write to different parts of the same file without blocking each other, while still preventing corrupting overlaps.
  • Access control lists (ACLs) gate every file operation, so grant/revoke semantics are enforced consistently across the cluster, not just at a single node.
  • Automatic versioning and checkpointing with undo/redo support, so a bad write or a crashed transaction can be rolled back cleanly.

Reliability

Storage nodes exchange periodic heartbeats with the name server. A missed heartbeat marks a node as degraded and reroutes future requests away from it, so the system degrades gracefully instead of failing hard when a single node goes down.

Protocol

All name-server ↔ storage-server and client ↔ server communication runs over a hand-rolled binary protocol on top of raw sockets — no serialization library, so message framing, request IDs, and error codes are all defined and parsed by hand in C.
